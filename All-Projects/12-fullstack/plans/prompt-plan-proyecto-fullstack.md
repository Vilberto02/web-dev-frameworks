# Contexto para el agente

Actúa como un mentor senior de desarrollo fullstack que va a diseñar un plan de estudio/práctica intensivo de **2 días como máximo** para un estudiante universitario que va a tener una entrevista técnica con prueba de conocimientos para un puesto de **practicante profesional de desarrollo de sistemas TI**.

## Mi situación
- Ya pasé una primera entrevista (de conocimiento general/fit).
- La siguiente etapa es una **entrevista técnica con casos prácticos a resolver**.
- Tengo conocimientos básicos/intermedios en las tecnologías del stack, pero quiero reforzarlos construyendo un **proyecto fullstack pequeño y completo desde cero**, que toque todos los puntos que me van a evaluar.
- Tengo un máximo de **2 días** para hacerlo (dedicando varias horas cada día), así que el proyecto debe ser pequeño pero representativo, no algo gigante o inacabable.

## Stack tecnológico que debo practicar (obligatorio incluirlo todo)
- **Frontend:** ReactJS + TypeScript + Tailwind CSS
- **Backend:** Node.js + APIs REST
- **Base de datos:** PostgreSQL (consultas y mantenimiento básico)
- **Diseño responsive** (mobile / tablet / desktop)
- **Buenas prácticas:** Clean Code, control de versiones con Git (ramas, commits, PRs simulados)
- **Pruebas:** funcionales y de integración básicas
- **Documentación:** del proceso técnico y funcionalidades (README, comentarios, docs de API)
- **Levantamiento de requerimientos:** aunque sea simulado/simplificado, quiero practicar cómo definiría requerimientos básicos de un mini-sistema
- **Uso de herramientas de IA** como apoyo al desarrollo (quiero documentar cómo las usé, no solo copiar código)

## Lo que necesito que hagas
Diseña un **plan de proyecto de 2 días**, con las siguientes características:

1. **Propuesta de proyecto**: sugiere una idea de aplicación pequeña (tipo CRUD con algo de lógica de negocio) que permita tocar TODO el stack de arriba sin ser excesivamente compleja. Ideas de referencia: gestor de tareas, sistema de inventario simple, gestor de citas, biblioteca de libros, etc. Elige o propón la que consideres más completa para demostrar habilidades en poco tiempo.

2. **Levantamiento de requerimientos exprés**: una sección corta donde se definan requerimientos funcionales básicos (historias de usuario simples) del proyecto elegido, como si yo mismo los hubiera "levantado".

3. **Diseño de base de datos**: modelo de datos simple en PostgreSQL (2-4 tablas con al menos una relación uno-a-muchos y, si es posible, una muchos-a-muchos), con su diagrama o descripción de tablas.

4. **Plan día por día y hora por hora aproximado** (bloques de 2-3 horas), dividiendo entre:
   - Día 1: configuración del proyecto, backend (API REST + conexión a PostgreSQL + validaciones + pruebas básicas), y avance de git desde el inicio.
   - Día 2: frontend (React + TypeScript + Tailwind, responsive, consumo de la API), pruebas de integración, documentación final y repaso de conceptos teóricos que podrían salir en la prueba de conocimientos.

5. **Checklist de buenas prácticas** a aplicar durante el desarrollo (Clean Code, estructura de carpetas, manejo de errores, convenciones de commits, etc.).

6. **Plan de control de versiones**: cómo debería estructurar mis ramas y commits en Git a lo largo del proyecto para que quede como evidencia de buenas prácticas (ej. `main`, `develop`, `feature/backend-api`, `feature/frontend-ui`, etc.) con ejemplos de mensajes de commit.

7. **Sección de documentación final**: qué debo incluir en el README del proyecto (descripción, tecnologías, instrucciones de instalación, endpoints documentados, capturas o diagramas si aplica).

8. **Repaso teórico complementario**: al final del plan, incluye una lista corta de conceptos teóricos clave (de React, Node.js, PostgreSQL y Git) que debería repasar en paralelo, ya que la prueba también podría incluir preguntas conceptuales además de los casos prácticos.

## Restricciones importantes
- El plan debe ser **realista para 2 días** (no un proyecto de semanas). Prioriza calidad y cobertura de conceptos sobre cantidad de funcionalidades.
- No necesito diseño visual elaborado, sino que se vea limpio, ordenado y responsive.
- Prefiero que el proyecto sea simple pero bien ejecutado, con buenas prácticas visibles, antes que algo ambicioso a medio terminar.
- Al final del plan, dame una lista de "banderas rojas" o errores comunes que debo evitar durante la prueba técnica real (based on the case types I might face).

Genera el plan completo, estructurado con títulos y subtítulos claros, listo para que yo lo siga paso a paso.
